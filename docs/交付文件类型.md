这是一个从「产物交付」视角拆解游戏公司岗位结构的问题。我先用一张全景图建立整体印象，再逐层展开。
以上是按交付物类型划分的 6 大类结构。下面展开每个类别下的具体岗位与产出形式：

---

## 一、文档 / 规范类 — 产出物为「可阅读的文本/图表」

| 岗位              | 典型交付物                           | 载体格式                     |
| ----------------- | ------------------------------------ | ---------------------------- |
| 系统策划          | GDD、系统设计文档、交互流程图        | Markdown / Notion / 腾讯文档 |
| 数值策划          | 数值模型文档、经济循环图、平衡性分析 | Excel / 在线表格             |
| 关卡策划          | 关卡白盒文档、关卡流程图、节奏曲线   | 文档 + 示意图                |
| 叙事策划          | 世界观设定集、对白脚本、分支剧情树   | Markdown / Twine / Excel     |
| 战斗策划          | 战斗规则文档、技能设计表             | 文档 + 表格                  |
| 技术策划 (TD)     | 技术设计文档、工具需求说明           | 文档 + 原型截图              |
| 技术负责人/架构师 | 技术架构文档、API 设计文档           | Markdown / Confluence        |
| 美术总监          | 美术风格指南、视觉规范文档           | PDF / Figma                  |
| 制作人/项目经理   | 里程碑计划、排期表、风险评估         | Excel / 项目管理工具         |
| 数据分析师        | 数据报告、玩家画像、留存漏斗         | BI 看板 / PDF                |
| 用户研究员        | 可用性测试报告、玩家访谈记录         | 文档 / 视频记录              |

**核心特征**：产出物不直接进入游戏包体，是上游决策和中间协调的介质。

---

## 二、代码 / 二进制类 — 产出物被编译或直接执行

| 岗位             | 典型交付物                   | 载体格式                |
| ---------------- | ---------------------------- | ----------------------- |
| 客户端程序       | 游戏客户端功能模块、UI 逻辑  | .gd / .cs / .cpp (源码) |
| 服务端程序       | 匹配系统、排行榜、数据持久层 | .go / .py / .java       |
| 引擎/工具程序    | 编辑器插件、资源管线工具     | 可执行文件 + 源码       |
| 渲染/图形程序    | Shader、渲染管线特性         | .glsl / .hlsl           |
| 技术美术 (TA-TD) | 材质函数、程序化生成工具     | Shader + 蓝图/脚本      |
| 构建/DevOps      | CI/CD 流水线、自动构建脚本   | yaml / py / 二进制包    |
| 自动化测试       | 测试框架、回归测试用例       | 测试脚本                |

**核心特征**：产出物直接编译为可执行逻辑，是游戏运行的必要条件。

---

## 三、视觉资产类 — 产出物为像素/顶点构成的视觉资源

| 岗位              | 典型交付物                   | 载体格式               |
| ----------------- | ---------------------------- | ---------------------- |
| 概念设计师        | 角色/场景概念图              | PSD / PNG              |
| 角色原画          | 角色设定图、表情集           | PSD / PNG              |
| 场景原画          | 场景氛围图、建筑设计图       | PSD / PNG              |
| 2D 角色/动画师    | Spine 骨骼动画、序列帧       | Spine 工程 / 精灵表    |
| 3D 角色建模       | 角色模型 (高低模)            | FBX / OBJ / GLTF       |
| 3D 场景建模       | 场景模型、道具模型           | FBX / OBJ              |
| 骨骼绑定/动画师   | 角色动画、过场动画           | FBX / Anim 文件        |
| 特效师 (VFX)      | 粒子特效、技能特效、环境特效 | 引擎内特效资源         |
| UI 设计师         | UI 界面、图标、字体排版      | PSD / 引擎内 UI 预制体 |
| 技术美术 (TA-Art) | 材质球、灯光预设、后处理配置 | 引擎内 TA 资源         |
| 视频制作          | 宣传片、过场动画             | MP4                    |

**核心特征**：产出物是感官层面的视觉素材，直接进入玩家眼中。

---

## 四、音频资产类 — 产出物为声波数据

| 岗位             | 典型交付物                  | 载体格式            |
| ---------------- | --------------------------- | ------------------- |
| 作曲/音乐制作    | 背景音乐 (BGM)、主题曲      | WAV / OGG / MP3     |
| 音效设计师 (SFX) | UI 音效、环境音、技能音效   | WAV / OGG           |
| 配音导演         | 配音统筹、语音表演指导      | 文档 + 录音         |
| 配音演员         | 角色语音素材                | WAV                 |
| 音频程序/集成    | 音频中间件集成 (Wwise/FMOD) | 音频工程文件 + 代码 |

**核心特征**：全部以音频文件形式交付，通常在引擎外制作、引擎内集成。

---

## 五、配置 / 数据类 — 产出物为结构化数据，被引擎/服务端读取

| 岗位       | 典型交付物                        | 载体格式              |
| ---------- | --------------------------------- | --------------------- |
| 数值策划   | 数值配置表 (属性/掉落/成长/经济)  | xlsx → csv / json     |
| 关卡策划   | 关卡配置 (敌人波次/触发器/刷怪点) | json / 引擎内关卡数据 |
| 系统策划   | 活动配置、任务配置                | json / yaml           |
| 本地化专员 | 多语言文本表                      | csv / po / xlsx       |
| 运营策划   | AB 测试分组配置、运营活动参数     | json / 后台配置       |

**核心特征**：非代码、非资产，是「数据驱动」层的核心——改一行数值不需要重新编译。

---

## 六、运营 / 传播内容类 — 产出物面向玩家或外部渠道

| 岗位          | 典型交付物                         | 载体格式        |
| ------------- | ---------------------------------- | --------------- |
| 社区运营      | 社区公告、社交媒体内容、开发者日志 | 图文 / 视频     |
| 市场策划      | 营销方案、渠道投放策略             | 文档            |
| 商务/渠道     | 渠道合作协议、上架物料包           | 文档 + 宣传素材 |
| 视频/内容制作 | 宣传视频、直播内容、GIF 动图       | MP4 / GIF       |
| 客服          | 客服话术库、FAQ 文档               | 文档            |
| PR/公关       | 媒体稿件、采访提纲                 | 文档            |

**核心特征**：不进游戏包体，但直接影响玩家获取、留存和品牌。
