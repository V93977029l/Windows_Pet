## P1 —— 高优先级

### 1. 测试覆盖率不足（估 < 30%）

- **已覆盖：** `config_manager.gd`（14 用例）、`mouse_manager.gd`（11 用例）
- **仍缺少的核心组件：**
  - `modules/pet/scripts/pet.gd` — 核心控制器（~300行）
  - `modules/display/scripts/material_manager.gd` — 材质预设系统
  - `modules/display/scripts/vector_renderer.gd` — SVG 渲染
  - `modules/effects/scripts/liquid_glass_controller.gd` — 液态玻璃特效
  - `modules/settings/ui/settings_window.gd` — 设置 UI 逻辑
  - `modules/settings/ui/throw_settings_dialog.gd` — 抛射参数 UI 逻辑
  - `core/autoload/save_manager.gd` — 存档服务
  - `core/autoload/data_manager.gd` — 数据管理器
  - `core/autoload/scene_manager.gd` — 场景管理
  - `core/services/tray_manager.gd` — 系统托盘
  - `core/services/audio_manager.gd` — 音频管理
- **现有测试质量不足：** `test_drag_controller.gd` 仅测参数设置，不测抛射物理/碰撞/边界
- **目标：** 渐进式补测试

## P2 —— 中优先级

### 2. 自动部署到 GitHub Releases

- **现状：** CI 仅上传 artifact，需手动进 Actions 页面下载
- **目标：** main 分支 push 后自动创建 GitHub Release 并上传 Windows exe
- **涉及文件：** `.github/workflows/ci.yml`

### 3. PR 测试报告展示

- **现状：** 测试结果仅存为 artifact（zip），不便直接查看
- **目标：** 使用 `dorny/test-reporter` 在 PR 页面直接展示测试通过/失败详情
- **涉及文件：** `.github/workflows/ci.yml`

### 4. 代码覆盖率报告

- **现状：** 无覆盖率数据
- **目标：** GdUnit4 生成 XML 覆盖率报告，CI 上传并在 PR 中展示
- **涉及文件：** `.github/workflows/ci.yml`

### 5. 场景结构契约验证

- **现状：** 无自动化场景完整性验证
- **目标：** CI 中添加 Godot headless 脚本，加载关键场景并断言必要节点存在
- **涉及文件：** `.github/workflows/ci.yml` + 新增验证脚本

## P3 —— 低优先级

### 6. AI 自修复反馈

- **现状：** CI 失败无结构化输出供 AI 消费
- **目标：** CI 失败时生成 JSON 格式失败报告作为 artifact，AI 下次对话可读取并修复

### 7. 两阶 Issue 体系

- **现状：** `working_log.md` 和 `issues.md` 为空文件，从未使用
- **目标：** 开始记录反复出现的问题（如"Godot 4.x class_name 必须在 extends 前"），激活跨对话记忆

### 8. tools/ 目录

- **现状：** 无自定义编辑器工具（`@tool` 脚本）
- **目标：** 视需要创建（如自动验证脚本、场景骨架检查器）
