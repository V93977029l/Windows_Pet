# 架构改进待办项

> 仅包含架构、工程基础设施、CI/CD 等与游戏具体内容无关的改进项。
> 游戏玩法/内容相关事项见独立文档。

---

## P0 —— 紧急（直接影响架构核心约束）

### 1. EventBus 完全未被使用

- **现状：** `core/autoload/event_bus.gd` 实现完善，但全项目无任何 `EventBus.publish()` / `EventBus.subscribe()` 调用
- **影响：** 架构的核心解耦机制形同虚设，所有模块间通信依赖 `pet.gd` 直接操控子模块
- **目标：** 模块间通信逐步迁移至 EventBus 发布-订阅模式
- **涉及文件：**
  - `modules/pet/scripts/pet.gd` — 改为发布事件，而非直接调用 `interaction_controller.drag.update_drag()`
  - `modules/settings/ui/throw_settings_dialog.gd` — 参数变更时发布事件而非 `pet_node.update_throw_params()`
  - `modules/settings/ui/settings_window.gd` — 设置变更时发布事件

### 2. CI 测试失败不阻塞构建

- **现状：** `ci.yml` 中测试步骤设了 `continue-on-error: true`
- **影响：** 全部测试失败 CI 仍绿色，质量门禁完全失效
- **目标：** 移除 `continue-on-error`，新增代码覆盖率收集步骤
- **涉及文件：** `.github/workflows/ci.yml`

## P1 —— 高优先级（影响可维护性和质量保障）

### 3. 测试覆盖率极低（估 < 15%）

- **无测试覆盖的核心组件：**
  - `modules/pet/scripts/pet.gd` — 核心控制器（~300行）
  - `modules/interaction/scripts/mouse_manager.gd` — 像素级碰撞检测
  - `modules/display/scripts/material_manager.gd` — 材质预设系统
  - `modules/display/scripts/vector_renderer.gd` — SVG 渲染
  - `modules/effects/scripts/liquid_glass_controller.gd` — 液态玻璃特效
  - `modules/settings/ui/settings_window.gd` — 设置 UI 逻辑
  - `modules/settings/ui/throw_settings_dialog.gd` — 抛射参数 UI 逻辑
  - `core/autoload/config_manager.gd` — 配置加载/保存
  - `core/autoload/save_manager.gd` — 存档服务
  - `core/autoload/data_manager.gd` — 数据管理器
  - `core/autoload/scene_manager.gd` — 场景管理
  - `core/services/tray_manager.gd` — 系统托盘
  - `core/services/audio_manager.gd` — 音频管理
- **现有测试质量不足：** `test_drag_controller.gd` 仅测参数设置，不测抛射物理/碰撞/边界
- **目标：** 按模块逐个补测试，优先 `pet.gd`、`config_manager.gd`、`mouse_manager.gd`

### 4. 硬编码节点路径（耦合隐患）

- **位置：** `modules/interaction/scripts/drag_controller.gd:70` — `parent_node.get_node("Slime")`
- **影响：** 场景中节点改名即静默失败
- **目标：** 通过构造参数或信号传入目标节点引用

### 5. API 契约未强制执行

- **现状：** 5个模块都有 `api.gd` 定义接口（信号+方法签名），但仅 `liquid_glass_controller.gd` 真正 `extends PetEffectsAPI`
- **未继承 API 的实现类：**
  | 模块 | API 类 | 实现类 |
  |------|--------|--------|
  | display | `PetDisplayAPI` | `material_manager.gd` (`extends RefCounted`) |
  | interaction | `PetInteractionAPI` | `drag_controller.gd` (`extends RefCounted`) |
  | pet | (无 class_name) | `pet.gd` (`extends Node2D`) |
  | settings | `PetUIApi` | `settings_window.gd` (`extends Window`) |
- **影响：** `api.gd` 沦为"文档注释"，编译器不强制约束
- **目标：** 让各实现类继承对应 API 类，或将 API 改为 interface/虚基类模式

## P2 —— 中优先级（改善长期维护体验）

### 6. 原型代码污染生产路径

- **位置：** `core/utils/constants.gd` 中的 `LIQUID_GLASS_SCENE` 指向 `res://prototypes/...`
- **影响：** 违反 `prototypes/` 目录的隔离原则
- **目标：** 将液态玻璃场景正式迁入 `modules/effects/scenes/`，更新常量引用

### 7. 缺少 `core/ui_framework/`

- **现状：** 架构规范规划的 UI 基础设施目录不存在
- **影响：** 设置窗口等 UI 没有统一的基类和主题管理
- **目标：** 视需要创建 `base_window.gd`、公共 UI 组件和主题资源

### 8. CI 缺少导出模板下载

- **现状：** CI 仅下载 Godot 引擎，未下载 Export Templates
- **影响：** 导出步骤静默失败（已 `continue-on-error` 掩盖）
- **目标：** 在 CI 中添加导出模板下载步骤，移除 `continue-on-error`
