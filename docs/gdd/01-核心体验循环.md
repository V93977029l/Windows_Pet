# 01 — 核心体验循环 (Core Experience Loop)

> **所属 GDD**：TransparentPet | **章节状态**：v0.1.0-draft
> **设计支柱关联**：支柱 1（陪伴在场感）、支柱 2（即时把玩手感）、支柱 3（收集驱动好奇）

---

## 设计目标

桌宠不是传统游戏，没有"关卡""胜负""结束"。它的循环是**持续在场、低强度、偶发交互**的。本章节定义三层循环，确保玩家在 30 秒、20 分钟、跨周三个时间尺度上都有满足感。

**核心假设（待验证）**：玩家平均每天与桌宠交互 3-8 次，单次 10-60 秒，每日总交互时长 2-5 分钟。

---

## 一、Moment-to-Moment 循环（0–30 秒）

这是玩家与宠物单次接触的微观循环。**必须每次都成立**——任何一次接触感觉"没意思"都会削弱陪伴感。

```
┌─────────────────────────────────────────────────────────┐
│                  MOMENT 循环（0-30s）                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ① 注意捕获          ② 互动发生          ③ 反馈给予    │
│   ─────────          ─────────          ─────────       │
│   余光瞥见宠物        点击/拖拽/抛射      形变/表情/音效  │
│   在做某事            （或只是观看）      即时呈现        │
│         │                  │                  │         │
│         └──────────────────┴──────────────────┘         │
│                            │                            │
│                            ▼                            │
│                   ④ 情绪/状态微变化                      │
│                   ─────────                             │
│                   互动影响宠物情绪                        │
│                   情绪影响下次行为表现                    │
│                            │                            │
│                            └──────────► 回到 ①           │
└─────────────────────────────────────────────────────────┘
```

| 阶段         | 玩家动作                    | 宠物反馈                                 | 支柱   |
| ------------ | --------------------------- | ---------------------------------------- | ------ |
| ① 注意捕获   | 余光瞥见 / 主动看           | 正在执行自主行为（走动、发呆、玩耍）     | 支柱 1 |
| ② 互动发生   | 点击 / 拖拽 / 抛射 / 仅观看 | 响应输入（被拖时跟手、被抛时飞行）       | 支柱 2 |
| ③ 反馈给予   | 观察反馈                    | 形变（液态玻璃挤压）、表情变化、音效     | 支柱 2 |
| ④ 情绪微变化 | 无（被动）                  | 互动 +情绪，冷落 -情绪；情绪驱动下个行为 | 支柱 1 |

**Moment 循环的"手感假设"（待调优）**：

- 拖拽响应延迟 ≤ `[PLACEHOLDER]` ms（建议 16ms 内，即一帧）
- 抛射后落地总时长 `[PLACEHOLDER]` s（建议 1.5-3s，太短无重量感，太长打断节奏）
- 互动后情绪可见变化延迟 ≤ `[PLACEHOLDER]` s（建议 0.3s 内）

## 二、Session 循环（5–30 分钟 / 单次坐在电脑前）

一次工作会话（如写代码、看文档）期间，玩家与宠物的多次接触构成 Session 循环。这个循环要回答："为什么这次坐下来，宠物让我的体验变好了？"

```
┌─────────────────────────────────────────────────────────────┐
│                   SESSION 循环（5-30min）                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   工作中        偶发休息       与宠物互动      回到工作       │
│   ──────       ──────        ──────         ──────          │
│   宠物在场      想放松一下     拖拽/抛射/      带着轻松感     │
│   自主活动      余光看到宠物   喂食/逗弄       继续专注       │
│   不打扰         │              │              │             │
│      ▲           ▼              ▼              ▼             │
│      │           └──────────────┴──────────────┘             │
│      │                  解压满足                            │
│      └──────────────────────────────────────────┘           │
│                    （单次会话重复 N 次）                      │
│                                                             │
│   会话结束时：宠物可能触发"告别/睡眠"等收尾行为               │
└─────────────────────────────────────────────────────────────┘
```

**Session 循环设计要点**：

| 要点       | 说明                                              | 关联机制               |
| ---------- | ------------------------------------------------- | ---------------------- |
| 在场不打扰 | 工作时宠物自主活动，鼠标穿透不抢焦点              | 自主行为系统、鼠标穿透 |
| 休息可达性 | 玩家想放松时，宠物随手可及（桌面任意位置）        | 窗口置顶、拖拽         |
| 互动轻量化 | 单次互动 10-30s，不强制流程，随时可中断           | 互动反馈系统           |
| 情绪连续性 | 跨 Session 情绪不重置，宠物"记得"最近被对待的方式 | 情绪系统               |

**Session 循环的"频率假设"（待验证）**：

- 单次工作会话内，玩家主动互动 `[PLACEHOLDER]` 次（建议 3-6 次）
- 自主行为触发间隔 `[PLACEHOLDER]` s（建议 30-120s，过密打扰，过疏失存在感）
- 单次会话总时长 `[PLACEHOLDER]` min（假设 20-40min，需调研）

## 三、Long-term 循环（小时–周 / 跨会话）

跨多次会话的长期循环，回答"玩家为什么明天还开着它"。这是支柱 3（收集驱动）的主战场。

```
┌──────────────────────────────────────────────────────────────┐
│                LONG-TERM 循环（小时-周）                       │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   每日开启          积累互动          触发解锁        收集册    │
│   ──────          ──────          ──────         ──────       │
│   系统托盘/        互动次数、       达成成就        新内容入册  │
│   开机自启         在线时长、       条件满足        可装备/展示 │
│   宠物迎接         情绪累计         （里程碑）      仪式感反馈  │
│      │               │               │               │        │
│      └───────────────┴───────────────┴───────────────┘        │
│                          │                                   │
│                          ▼                                   │
│                   知道下个目标，                              │
│                   "明天再来看看"                              │
│                          │                                   │
│                          └─────────► 回到 每日开启            │
└──────────────────────────────────────────────────────────────┘
```

**Long-term 循环设计要点**：

| 要点       | 说明                                           | 关联机制       |
| ---------- | ---------------------------------------------- | -------------- |
| 每日仪式   | 开机/启动时宠物有迎接行为，建立"它等我"的感觉  | 自主行为系统   |
| 被动积累   | 不要求玩家"肝"，在线时长和偶发互动自然推进解锁 | 成就与收集册   |
| 目标可见   | 玩家随时知道下个解锁是什么、还差多少           | 收集册 UI      |
| 解锁仪式感 | 解锁瞬间有专门反馈，不只是 toast 通知          | 收集解锁系统   |
| 无负担     | 不设计每日任务、签到、断签惩罚（反对动机）     | 见 02-玩家动机 |

**Long-term 循环的"留存假设"（待验证）**：

- 新内容解锁间隔 `[PLACEHOLDER]` 天（建议活跃玩家 2-4 天一个，避免太密贬值、太疏遗忘）
- 首周可解锁内容总数 `[PLACEHOLDER]` 个（建议 8-12 个，保证首周有持续惊喜）
- 全内容解锁总时长 `[PLACEHOLDER]` 小时（建议 30-60 天自然游玩，非挂机）

## 四、三层循环的衔接关系

三层循环**不是独立**的，而是嵌套与强化关系：

```
Long-term 收集解锁
    │
    │ 提供"新皮肤/新表情/新行为"→ 丰富 Moment 的反馈多样性
    │
    ▼
Session 解压满足
    │
    │ 多次 Moment 的正向反馈累积 → 强化"工作时有它真好"的Session记忆
    │
    ▼
Moment 即时反馈
    │
    │ 每次接触的愉悦 → 维持玩家在 Session 中持续开启宠物的意愿
    │
    ▼
支撑 Long-term 在线时长积累 → 推进解锁
```

**关键设计约束**：

- Moment 循环**必须独立成立**——即便没有任何解锁系统，单次互动也要好玩。这是基础。
- Session 循环依赖 Moment 的反复成立 + 情绪连续性。
- Long-term 循环是**加分项而非必需**——若收集系统未实现，Moment + Session 仍应支撑产品价值（但留存会弱）。

## 五、循环失效模式（Failure States）

提前定义"循环坏了"长什么样，便于 playtest 时识别：

| 循环层    | 失效表现             | 可能根因                                 | 对应章节               |
| --------- | -------------------- | ---------------------------------------- | ---------------------- |
| Moment    | 玩家拖一次就不再拖了 | 手感差：延迟、重量感缺失、反馈弱         | 03-互动反馈系统        |
| Moment    | 玩家说"它就是张图"   | 自主行为缺失或不可见                     | 03-自主行为系统        |
| Session   | 玩家工作时关掉宠物   | 自主行为打扰（过频、抢焦点、声音吵）     | 自主行为系统、鼠标穿透 |
| Session   | 玩家说"没意思就关了" | 情绪无变化，互动无累积感                 | 03-情绪系统            |
| Long-term | 玩家第三天就不开了   | 解锁太慢 / 目标不可见 / 无每日仪式       | 04-成就与收集册        |
| Long-term | 玩家说"太肝了"       | 解锁条件强制互动、设计成任务而非自然积累 | 04-成就与收集册        |
