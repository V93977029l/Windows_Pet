# 07 — 现有功能体验规格化

> **所属 GDD**：TransparentPet | **状态**：v0.1.0-draft
> **目的**：把已实现的工程功能，从"实现了什么"转写成"玩家应感受到什么 + 调优杠杆 + 失败态"
> **来源**：基于 [桌宠开发日志.md](../桌宠开发日志.md) v0.1.0-RELEASE 与 [项目结构总览.md](../项目结构总览.md)

---

## 设计目标

项目已发布 v0.1.0 内测版，但这些功能此前只从**工程视角**记录（"实现了像素级鼠标穿透"）。本章节将它们转写为**玩家体验规格**，使其符合 GDD 标准，并明确每个功能的：

- 玩家体验目标（玩家应感受到什么）
- 调优杠杆（哪些参数影响手感）
- 失败状态（坏了长什么样）
- GDD 改进方向（现有功能如何服务三支柱）

---

## 一、透明窗口 + 始终置顶

### 工程现状

- 无边框、透明背景、始终置顶（可开关）、不可调整大小、启动居中
- project.godot 配置：`transparent=true`, `always_on_top=true`, `borderless=true`

### 玩家体验规格

| 维度             | 规格                                                    |
| ---------------- | ------------------------------------------------------- |
| **体验目标**     | 宠物像真实存在于桌面上，不是"在一个窗口里"              |
| **玩家应感受到** | 它贴在桌面上，不被其他窗口盖住，但也不挡我操作          |
| **成功条件**     | 玩家描述宠物时说"在桌面上"而非"在窗口里"                |
| **失败状态**     | 宠物被其他窗口盖住（置顶失效）/ 挡住关键 UI（置顶过强） |

### 调优杠杆

| 杠杆          | 现状         | GDD 建议                                       |
| ------------- | ------------ | ---------------------------------------------- |
| always_on_top | 默认开，可关 | 保留，但默认开（保证可见性）                   |
| 启动位置      | 屏幕居中     | 改为底部居中（不挡工作区，详见 06-onboarding） |
| 窗口大小      | 跟随宠物精灵 | 保留（宠物多大窗口多大）                       |

### 支柱服务

服务**支柱 1（陪伴在场感）**——透明 + 置顶是"它存在于我的桌面"的物理基础。

## 二、像素级鼠标穿透

### 工程现状

- 基于 alpha 通道逐像素检测，非矩形包围盒
- 鼠标不在宠物上时，窗口穿透所有点击
- 鼠标在宠物上时，穿透关闭可交互
- GDExtension 调用 Windows `WS_EX_TRANSPARENT` / `WS_EX_LAYERED`

### 玩家体验规格

| 维度             | 规格                                            |
| ---------------- | ----------------------------------------------- |
| **体验目标**     | 宠物不干扰桌面任何操作，只在我想碰它时才响应    |
| **玩家应感受到** | "它在那里但完全不碍事"，工作完全不受影响        |
| **成功条件**     | 玩家工作 1 小时内不被宠物打断任何一次操作       |
| **失败状态**     | 宠物挡住按钮点不到 / 穿透失效点穿到宠物身后窗口 |

### 调优杠杆

| 杠杆         | 现状         | GDD 建议                                  |
| ------------ | ------------ | ----------------------------------------- |
| 穿透检测精度 | 像素级 alpha | 保留（已是最佳）                          |
| 穿透切换响应 | 即时         | 保留                                      |
| 边缘容差     | 无           | 考虑加 `[P]` 2-3px 容差，避免边缘点击误判 |

### 支柱服务

服务**支柱 1**——"不打扰"是陪伴感的前提。这是项目**最强差异化点**，多数劣质桌宠死在这里。

## 三、拖拽交互

### 工程现状

- 鼠标左键按住宠物实体可自由拖动
- 像素级检测保证只有点中宠物才能拖
- DragController 统一输入处理

### 玩家体验规格

| 维度             | 规格                             |
| ---------------- | -------------------------------- |
| **体验目标**     | 拖拽跟手、有质量感，是解压出口   |
| **玩家应感受到** | "它跟我的手"，像拖一个软的实物   |
| **成功条件**     | 玩家烦躁时会下意识拖它（非刻意） |
| **失败状态**     | 延迟感 / 轻飘感 / 拖动卡顿       |

### 调优杠杆（详见 [05-调优变量表.md](05-调优变量表.md)）

| 杠杆     | 现状     | GDD 改进方向                           |
| -------- | -------- | -------------------------------------- |
| 跟手模式 | 直接跟随 | 评估弹性跟手（加质量感），但延迟 ≤16ms |
| 拖拽形变 | 无/部分  | 增加惯性拉伸形变（支柱 2 手感关键）    |
| 情绪联动 | 无       | 接入情绪系统（轻柔+愉悦、粗暴-愉悦）   |

### 支柱服务

服务**支柱 2（即时把玩手感）**——拖拽是最高频互动，手感必须打磨。

## 四、抛射物理

### 工程现状

- 拖拽松手，速度超阈值则抛射
- 重力下落 + 屏幕边缘弹性反弹 + 地面摩擦减速
- 参数可配置（重力、最小/最大速度、速度放大系数）
- 抛射开关可关

### 玩家体验规格

| 维度             | 规格                                          |
| ---------------- | --------------------------------------------- |
| **体验目标**     | 抛射有重量感和弹性，是核心解压动作            |
| **玩家应感受到** | "扔出去真爽，弹起来真解压"                    |
| **成功条件**     | 玩家主动抛射 > 拖拽次数的 30%（说明解压有效） |
| **失败状态**     | 飞太远找不到 / 弹太多次轻飘 / 落地死沉无弹性  |

### 调优杠杆（详见 [05-调优变量表.md](05-调优变量表.md)）

| 杠杆     | 现状           | GDD 建议                                 |
| -------- | -------------- | ---------------------------------------- |
| 重力     | 可配 100-3000  | 默认 `[P]` 1500，playtest 调             |
| 弹跳次数 | 由衰减系数决定 | 目标 `[P]` 3 次，太多轻飘太少死沉        |
| 落地形变 | 无             | **重点新增**：落地挤压形变（解压感核心） |
| 飞行形变 | 无             | 新增：飞行方向拉伸                       |
| 音效     | 无             | 新增：弹跳音效（默认关）                 |

### 支柱服务

服务**支柱 2**——抛射是支柱 2 的招牌动作，落地形变是**最高优先级改进项**。

## 五、系统托盘

### 工程现状

- 最小化到 Windows 托盘，常驻后台
- 左键打开设置，右键弹菜单（设置/退出）
- explorer 重启自动恢复托盘图标
- 任务栏图标隐藏（不占任务栏）

### 玩家体验规格

| 维度             | 规格                                 |
| ---------------- | ------------------------------------ |
| **体验目标**     | 宠物常驻但不碍事，随时可呼出         |
| **玩家应感受到** | "它一直在后台陪着我"                 |
| **成功条件**     | 玩家不因托盘图标而烦躁，且能快速呼出 |
| **失败状态**     | 托盘图标丢失 / 无法呼出 / 占任务栏   |

### 调优杠杆

| 杠杆       | 现状      | GDD 建议                       |
| ---------- | --------- | ------------------------------ |
| 托盘菜单   | 设置/退出 | 增加"收集册"入口（联动支柱 3） |
| 任务栏隐藏 | 已隐藏    | 保留（关键，不占任务栏）       |
| 开机自启   | 已实现    | 默认关，引导玩家自愿开启       |

### 支柱服务

服务**支柱 1**——托盘常驻是"它一直在"的技术保障，也是 Long-term 循环的物理基础。

## 六、设置窗口

### 工程现状

- `` ` `` 键或托盘左键打开
- 缩放（0.2x-4.0x，滑块+输入框）
- 材质切换（下拉，内置史莱姆材质）
- 动态效果开关（顶点波动）
- 窗口置顶开关
- 抛射参数配置（弹窗）
- 保存配置 / 恢复默认

### 玩家体验规格

| 维度             | 规格                                     |
| ---------------- | ---------------------------------------- |
| **体验目标**     | 玩家能快速调整宠物到舒适状态，不复杂     |
| **玩家应感受到** | "我想改的都能改，且改完立刻生效"         |
| **成功条件**     | 玩家能在 30s 内找到并修改任意配置项      |
| **失败状态**     | 设置项太多眼花 / 改了不生效 / 找不到入口 |

### 调优杠杆与 GDD 扩展方向

| 现有项       | GDD 评估                                  |
| ------------ | ----------------------------------------- |
| 缩放         | ✅ 保留，手感配置                         |
| 材质切换     | ✅ 保留，未来作为皮肤系统入口             |
| 动态效果开关 | ✅ 保留，性能/视觉权衡                    |
| 置顶开关     | ✅ 保留                                   |
| 抛射参数     | ✅ 保留，但建议高级用户才调（默认值要好） |

**GDD 建议新增**：
| 新增项 | 服务支柱 |
|---|---|
| 自定义页签（命名/行为倾向） | 支柱 3（自定义系统） |
| 收集册入口 | 支柱 3 |
| 音效开关 + 音量 | 支柱 2（互动音效） |
| 行为频率倾向（安静↔好动） | 支柱 1（自主行为） |

### 支柱服务

跨支柱——设置是玩家调控三支柱体验的统一入口。

## 七、史莱姆着色器

### 工程现状

- canvas_item ShaderMaterial
- 顶点动画（噪声波动，模拟液体晃动）
- 4 阶 FBM 分形噪声驱动扭曲
- 菲涅尔边缘光、高光、透明渐变

### 玩家体验规格

| 维度             | 规格                                      |
| ---------------- | ----------------------------------------- |
| **体验目标**     | 宠物质感"软、弹、有生命"，非静态贴图      |
| **玩家应感受到** | "它像果冻/史莱姆，会自己微微晃动"         |
| **成功条件**     | 玩家描述宠物时用"软/弹/活"而非"图片/贴图" |
| **失败状态**     | 动画太剧烈像故障 / 太弱看不出 / 干扰视觉  |

### 调优杠杆

| 杠杆         | 现状 | GDD 建议                            |
| ------------ | ---- | ----------------------------------- |
| 顶点波动幅度 | 可关 | 默认开，幅度可调（性能 vs 视觉）    |
| 菲涅尔强度   | 固定 | 可作为情绪表现通道（情绪高→边缘亮） |
| 高光强度     | 固定 | 同上，情绪联动                      |

### 支柱服务

服务**支柱 1（陪伴感）** + **支柱 2（手感）**——着色器让宠物"活"，形变让互动"爽"。这是项目**视觉差异化核心**。

## 八、SVG 矢量渲染

### 工程现状

- SVG 存储，Godot 导入为 ImageTexture
- 缩放时重新渲染为高分辨率位图（2x 超采样）
- 与材质系统解耦

### 玩家体验规格

| 维度             | 规格                        |
| ---------------- | --------------------------- |
| **体验目标**     | 任意缩放不失真，4K 屏也清晰 |
| **玩家应感受到** | "放大也清楚，不模糊"        |
| **成功条件**     | 4K 屏最大缩放下无可见锯齿   |
| **失败状态**     | 缩放后模糊 / 渲染卡顿       |

### 支柱服务

服务**支柱 2**——缩放自由度是手感的一部分（玩家可调到舒适大小）。技术基础，非体验差异化点。

## 九、液态玻璃特效（原型）

### 工程现状

- 独立原型场景（prototypes/liquid_glass/）
- SDF 形状系统（圆/超椭圆角矩形/史莱姆形）
- 折射/色散/菲涅尔/眩光光学模拟
- 双通道高斯模糊背景
- 参考开源项目 liquid-glass-studio

### 玩家体验规格（未来集成方向）

| 维度             | 规格                                 |
| ---------------- | ------------------------------------ |
| **体验目标**     | 互动时宠物形变如液态玻璃，质感真实   |
| **玩家应感受到** | "捏它像捏真实的软糖/玻璃"            |
| **成功条件**     | 互动形变让玩家产生"想再摸一次"的冲动 |
| **失败状态**     | 形变过度像故障 / 性能卡顿 / 视觉杂乱 |

### GDD 集成路径

液态玻璃原型是**支柱 2 的未来核心**——它能让"捏/形变"互动达到解压玩具级别的手感。

| 阶段 | 任务                                     |
| ---- | ---------------------------------------- |
| 当前 | 原型验证，未集成主程序                   |
| 短期 | 集成到拖拽/抛射的形变反馈                |
| 中期 | 实现"捏"互动（03-03 §3.5）               |
| 长期 | 情绪联动形变（开心时更弹、低落时更软塌） |

### 支柱服务

服务**支柱 2**——液态玻璃是"解压把玩"体验的质感天花板，是项目**长期差异化壁垒**。
