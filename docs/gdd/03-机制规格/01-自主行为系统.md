# 机制规格 — 自主行为系统 (Autonomous Behavior)

> **所属 GDD**：TransparentPet / 03-机制规格 | **状态**：v0.1.0-draft
> **设计支柱**：支柱 1（陪伴在场感）—— 本系统是支柱 1 的**核心载体**
> **依赖**：情绪系统（行为选择受情绪影响）、互动反馈系统（互动打断行为）、收集解锁系统（解锁新行为）

---

## 1. 机制目的 (Purpose)

让宠物在玩家不操作时"有自己的事在做"，从而产生"它是活的"的陪伴感。

**没有这个系统，桌宠就只是一张可拖拽的图**——这是劣质桌宠与优质桌宠的分水岭。

## 2. 玩家幻想 (Player Fantasy)

_"我在工作时它在自己的小世界里生活，偶尔我抬头看它，它正在发呆、散步、或者偷偷看我。"_

玩家应感觉到：

- 宠物有自主意志，不是等我操作的道具
- 宠物的行为有可预测性（能逐渐"读懂"它）又有惊喜感（偶尔做意外的事）
- 宠物的行为受我对待它的方式影响（被我常互动的宠物更黏人）

## 3. 输入 / 输出

| 类型     | 输入                                                                  | 输出 |
| -------- | --------------------------------------------------------------------- | ---- |
| 触发输入 | 时间流逝、情绪状态变化、玩家互动结束、环境事件（开机/关机/空闲检测）  | —    |
| 运行输入 | 当前情绪值、上次行为时间、玩家在线状态、当前时段（早/午/晚）          | —    |
| 输出     | 宠物执行某个行为（移动/表情/动作/音效），行为持续一段时间后结束或切换 | —    |

## 4. 行为库 (Behavior Library)

行为分三类，按"可见性"和"打扰度"组织：

### 4.1 基础行为（默认解锁，低打扰）

| 行为             | 描述                             | 持续时长              | 打扰度 | 触发情绪倾向 |
| ---------------- | -------------------------------- | --------------------- | ------ | ------------ |
| 发呆 (Idle)      | 原地静止，偶有眨眼/微动          | `[PLACEHOLDER]` 5-15s | 极低   | 中性         |
| 散步 (Wander)    | 在桌面小范围随机移动             | `[PLACEHOLDER]` 3-8s  | 低     | 中性/开心    |
| 看玩家 (Watch)   | 转向鼠标位置，盯着看一会儿       | `[PLACEHOLDER]` 2-5s  | 低     | 依恋         |
| 伸懒腰 (Stretch) | 形变拉伸动画                     | `[PLACEHOLDER]` 1-2s  | 极低   | 放松         |
| 睡眠 (Sleep)     | 长时间无互动时进入，轻微呼吸动画 | 持续至玩家互动        | 极低   | 疲倦         |

### 4.2 互动响应行为（玩家互动后触发）

| 行为       | 描述                                | 触发条件                                        |
| ---------- | ----------------------------------- | ----------------------------------------------- |
| 被拖挣扎   | 被拖拽时轻微形变抗拒/顺应           | 玩家拖拽中                                      |
| 落地弹跳   | 抛射落地后的弹跳（已有物理）        | 抛射落地                                        |
| 被关注开心 | 玩家长时间看它，它发现后表现开心    | Watch 行为 + 玩家鼠标静止悬停 `[PLACEHOLDER]` s |
| 求互动     | 情绪低时主动靠近鼠标/做动作吸引注意 | 情绪 < 阈值 + 玩家长时间无互动                  |

### 4.3 解锁行为（通过收集解锁系统获得）

| 行为        | 描述                               | 解锁来源 |
| ----------- | ---------------------------------- | -------- |
| 玩耍 (Play) | 自己玩某种小动作（翻滚、追尾巴等） | 成就解锁 |
| 唱歌 (Sing) | 发出轻柔音效序列                   | 成就解锁 |
| 特殊动作    | 皮肤专属动作（如史莱姆分裂）       | 皮肤解锁 |

**行为库设计原则**：

- 基础行为保证"它活着"的下限
- 解锁行为制造"它学会了新东西"的惊喜（服务支柱 3）
- 所有行为**不打断玩家操作**（鼠标穿透保证）

## 5. 行为选择机制 (Behavior Selection)

采用**加权随机 + 情绪偏置**，不使用复杂状态机（避免过度工程化）。

### 选择算法（伪代码）

```
每 [PLACEHOLDER] s（建议 30-120s）或行为结束时：
  candidates = 当前可执行行为（排除冷却中、条件不满足的）
  for each behavior in candidates:
    weight = base_weight
    weight *= emotion_modifier[behavior][current_emotion]  # 情绪影响
    weight *= time_of_day_modifier[behavior][current_time] # 时段影响
    weight *= recent_penalty[behavior]                     # 刚做过的降权
  selected = weighted_random(candidates, weights)
  执行 selected
```

### 情绪对行为的偏置示例

| 情绪 | 增强             | 抑制       |
| ---- | ---------------- | ---------- |
| 开心 | 散步、玩耍、唱歌 | 睡眠       |
| 低落 | 发呆、睡眠       | 散步、玩耍 |
| 依恋 | 看玩家、求互动   | —          |
| 疲倦 | 睡眠、发呆       | 玩耍、唱歌 |

## 6. 成功条件 (Success Condition)

| 验证项 | 标准                                          |
| ------ | --------------------------------------------- |
| 存在感 | 玩家工作 10 分钟内至少余光注意到宠物 1 次在动 |
| 可读性 | 玩家游玩 3 天后能说出至少 3 种宠物会做的事    |
| 不打扰 | 玩家工作期间不因宠物行为而分心/烦躁           |
| 惊喜感 | 玩家每周至少 1 次"它居然做了这个"的惊喜反馈   |

## 7. 失败状态 (Failure State)

| 失败     | 表现               | 根因                           | 修复方向                     |
| -------- | ------------------ | ------------------------------ | ---------------------------- |
| 失存在感 | 玩家忘了宠物存在   | 行为太少/太静态/触发太稀       | 增加行为频率或可见性         |
| 打扰感   | 玩家烦躁关闭宠物   | 行为太频繁/移动范围太大/有声音 | 降频、缩范围、默认静音       |
| 不可读   | 玩家觉得"随机乱动" | 行为差异度低、无情绪关联       | 强化情绪偏置、增加行为辨识度 |
| 卡死     | 宠物不动了         | 行为选择 bug、状态卡住         | 行为超时强制切换 + 日志      |

## 8. 边界情况 (Edge Cases)

| 情况                           | 处理                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| 玩家拖拽中触发行为选择         | 暂停行为选择，拖拽结束后恢复                                            |
| 玩家抛射宠物在飞行中           | 飞行物理优先，行为暂停，落地后恢复                                      |
| 多显示器                       | 散步行为限定在主显示器桌面范围（不跨屏，避免找不着）                    |
| 窗口被最小化到托盘             | 行为暂停（节省资源），恢复窗口时执行"迎接"行为                          |
| 玩家长时间离开电脑（空闲检测） | 进入睡眠行为，降低行为频率                                              |
| 解锁新行为瞬间                 | 新行为权重临时提升（让玩家尽快看到），持续 `[PLACEHOLDER]` 次后回归正常 |

## 10. 依赖关系

| 依赖方向           | 说明                             |
| ------------------ | -------------------------------- |
| ← 情绪系统         | 读取当前情绪作为行为选择输入     |
| → 互动反馈系统     | 行为可被玩家互动打断             |
| ← 收集解锁系统     | 读取已解锁行为列表               |
| → 显示模块（工程） | 行为需要驱动精灵/着色器表现      |
| → 音频系统（待建） | 部分行为需音效（默认静音可开关） |

## 11. 实现备注（设计层面，不规定代码）

- 行为库应数据驱动（配置文件定义行为列表），便于增删不改代码
- 行为选择器与具体行为解耦，新行为接入不改选择逻辑
- 状态需可序列化（睡眠中被关机，重启后恢复合理状态，不强行续睡）

## 12. 待验证假设

1. 行为选择间隔的"打扰临界点"（playtest 重点）
2. 散步移动范围在多分辨率下的体感
3. 解锁行为临时加权是否有效让玩家"发现"新内容
4. 空闲检测阈值（多久无操作算"离开"）
