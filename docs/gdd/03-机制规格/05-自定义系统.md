# 机制规格 — 自定义系统 (Customization)

> **所属 GDD**：TransparentPet / 03-机制规格 | **状态**：v0.1.0-draft
> **设计支柱**：支柱 3（收集驱动好奇）的延伸 —— 服务"表达"动机
> **依赖**：收集解锁系统（自定义选项来自解锁内容）、显示模块（外观渲染）

---

## 1. 机制目的 (Purpose)

让玩家将宠物个性化为"我的宠物"，通过投入个性化建立**禀赋效应**——玩家因"我配置的"而更不愿卸载。

**心理学依据**：行为经济学中的禀赋效应（endowment effect）——人对"自己投入过"的事物估值更高。让玩家命名、配置宠物，提升留存与付费意愿。

## 2. 玩家幻想 (Player Fantasy)

_"这是我的小蓝，我给它取了名字，选了喜欢的皮肤，调了它的活跃度。它和别人家的不一样。"_

玩家应感觉到：

- 宠物是"我的"，不是流水线产品
- 自定义选项足够丰富，能表达个性
- 自定义不影响核心体验（不会因配置坏掉）
- 命名让宠物有身份感

## 3. 自定义维度

| 维度     | 选项                    | 来源     | 影响           |
| -------- | ----------------------- | -------- | -------------- |
| 名字     | 玩家自定义文本          | 默认提供 | 称呼感、身份感 |
| 皮肤     | 已解锁皮肤中选择        | 收集解锁 | 外观           |
| 表情包   | 已解锁表情包中选择      | 收集解锁 | 表现风格       |
| 行为倾向 | 活跃度滑块（安静↔好动） | 默认开放 | 自主行为频率   |
| 互动偏好 | 默认开启的互动类型      | 默认开放 | 互动可用性     |
| 位置     | 桌面默认位置            | 默认开放 | 启动位置       |
| 音效     | 开关 + 音量             | 默认开放 | 打扰控制       |

### 3.1 命名系统（重点）

| 维度     | 规格                                             |
| -------- | ------------------------------------------------ |
| 长度     | `[P]` 1-8 字符（中英文混合）                     |
| 过滤     | 屏蔽敏感词（基础过滤，非重点）                   |
| 显示     | 设置中显示；宠物旁不常显（避免挡视野），悬停可显 |
| 默认名   | "小蓝"（史莱姆默认）/ 提供几个候选               |
| 情绪联动 | 命名时宠物表现开心（"它有名字了"的仪式感）       |

### 3.2 行为倾向滑块

| 维度 | 规格                                           |
| ---- | ---------------------------------------------- |
| 范围 | 安静(0) ↔ 好动(100)，默认 50                   |
| 影响 | 调整自主行为系统的行为选择间隔与移动类行为权重 |
| 目的 | 让"想要安静陪伴"和"想要活泼宠物"的玩家都满足   |
| 红线 | 即使最"好动"也不打扰工作（有打扰上限保护）     |

## 4. 成功条件 (Success Condition)

| 验证项     | 标准                              |
| ---------- | --------------------------------- |
| 投入感     | > `[P]` 70% 玩家会自定义至少 1 项 |
| 身份感     | 玩家能说出宠物的名字              |
| 个性表达   | 玩家觉得"我的宠物和别人的不一样"  |
| 不破坏体验 | 自定义不会让宠物"坏掉"或不可玩    |

## 5. 失败状态 (Failure State)

| 失败       | 表现                     | 根因                        | 修复方向              |
| ---------- | ------------------------ | --------------------------- | --------------------- |
| 不自定义   | 玩家用默认配置到底       | 自定义入口隐蔽/选项无吸引力 | 引导首次自定义        |
| 配置坏体验 | 自定义后宠物表现异常     | 极端配置未保护              | 配置钳制 + 默认回退   |
| 选择焦虑   | 选项太多玩家不知道选什么 | 选项过载                    | 默认值合理 + 分步引导 |
| 无差异感   | 自定义后体感无变化       | 自定义影响太弱              | 强化可见差异          |

## 6. 边界情况 (Edge Cases)

| 情况                         | 处理                                 |
| ---------------------------- | ------------------------------------ |
| 玩家不命名                   | 使用默认名，不强制                   |
| 名字含敏感词                 | 拒绝并提示，给默认建议               |
| 极端行为倾向配置             | 钳制到不影响核心体验的范围           |
| 自定义后卸载皮肤（不应发生） | 皮肤解锁后永久拥有，不存在此情况     |
| 多宠物（未来扩展）           | 当前单宠物设计，多宠物时每只独立配置 |

## 7. 调优杠杆

详见 [05-调优变量表.md](../05-调优变量表.md)：

| 杠杆             | 假设值       | 调优目的                 |
| ---------------- | ------------ | ------------------------ |
| 名字最大长度     | `[P]` 8 字符 | 表达 vs 显示空间         |
| 行为倾向影响强度 | `[P]`        | 自定义可见性 vs 打扰保护 |
| 默认行为倾向值   | `[P]` 50     | 首次体验基线             |

## 8. 依赖关系

| 依赖方向           | 说明                          |
| ------------------ | ----------------------------- |
| ← 收集解锁系统     | 读取已解锁皮肤/表情/行为      |
| → 自主行为系统     | 行为倾向影响行为选择          |
| → 显示模块（工程） | 皮肤/表情渲染                 |
| → 设置模块（工程） | 自定义 UI（已有设置窗口基础） |

## 9. 实现备注

- 自定义配置持久化到 `pet_config_user.cfg`（已有机制）
- 自定义 UI 复用现有设置窗口框架，扩展自定义页签
- 命名系统的"仪式感"可通过情绪系统联动实现（命名时 +愉悦）
