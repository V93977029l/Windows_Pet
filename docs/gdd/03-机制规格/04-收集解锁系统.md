# 机制规格 — 收集解锁系统 (Collection & Unlock)

> **所属 GDD**：TransparentPet / 03-机制规格 | **状态**：v0.1.0-draft
> **设计支柱**：支柱 3（收集驱动好奇）—— 本系统是支柱 3 的**核心载体**
> **经济模型**：无货币，采用成就/收集册驱动（见 [04-成就与收集册.md](../04-成就与收集册.md)）
> **依赖**：自主行为系统（解锁新行为）、显示模块（皮肤渲染）、自定义系统（解锁内容可装备）

---

## 1. 机制目的 (Purpose)

提供长期目标与"再看一眼"的回头理由，让玩家有持续发现的惊喜。

**红线**：收集必须**无负担**——不设计每日任务、断签惩罚、强制互动。解锁是自然游玩的副产品，不是工作。

## 2. 玩家幻想 (Player Fantasy)

_"我今天开机发现它学会了新动作 / 换了新皮肤，集齐收集册真有成就感。下个目标还差一点，明天再看看。"_

玩家应感觉到：

- 总知道下个能解锁什么、还差多远
- 解锁是"惊喜到来"而非"任务完成"
- 收集册是可回顾、可炫耀的成果
- 不会因没解锁而焦虑（无时间压力）

## 3. 可解锁内容类型

| 类型              | 描述                           | 数量规划       | 解锁来源   |
| ----------------- | ------------------------------ | -------------- | ---------- |
| 皮肤 (Skin)       | 宠物外观变体（颜色/材质/形状） | `[P]` 12-20 个 | 里程碑成就 |
| 表情 (Expression) | 额外表情包（除基础外）         | `[P]` 8-15 套  | 互动累计   |
| 行为 (Behavior)   | 新自主行为（唱歌、玩耍等）     | `[P]` 6-10 个  | 特定成就   |
| 场景道具 (Prop)   | 宠物周围可出现的小道具         | `[P]` 10-15 个 | 在线时长   |
| 称号 (Title)      | 收集册展示用称号               | `[P]` 8-12 个  | 特殊条件   |

**首周内容规划**：保证首周活跃玩家能解锁 `[P]` 8-12 个内容，维持新鲜感。

## 4. 解锁来源（无货币经济）

由于采用"仅成就/收集册"模型（无货币），解锁来源是**成就达成**，而非商店购买：

| 解锁来源   | 机制           | 示例                                 |
| ---------- | -------------- | ------------------------------------ |
| 里程碑成就 | 累计达到某数值 | "累计互动 100 次" → 解锁皮肤A        |
| 行为成就   | 完成特定行为   | "抛射宠物 50 次" → 解锁弹跳表情      |
| 时长成就   | 累计在线时长   | "累计在线 10 小时" → 解锁睡眠道具    |
| 探索成就   | 发现隐藏内容   | "凌晨 3 点打开宠物" → 解锁夜猫子称号 |
| 收集成就   | 集齐某类内容   | "集齐 5 个皮肤" → 解锁稀有皮肤       |

**详细成就清单见** [04-成就与收集册.md](../04-成就与收集册.md)。

## 5. 解锁仪式感 (Unlock Ceremony)

解锁瞬间必须有**专门反馈**，区别于普通成就提示，制造"这件事值得记住"的感觉：

| 阶段       | 反馈                                      | 说明                   |
| ---------- | ----------------------------------------- | ---------------------- |
| 触发瞬间   | 屏幕轻微闪光 + 专属音效（可关）           | 引起注意               |
| 解锁展示   | 宠物周围浮现解锁内容预览（皮肤/表情演示） | 让玩家看到"得到了什么" |
| 情绪联动   | 宠物表现开心（情绪系统 +愉悦）            | "它也为你高兴"         |
| 收集册更新 | 收集册对应位置点亮 + 新内容高亮           | 进度可见               |
| 可装备提示 | 提示玩家可在自定义中装备                  | 引导下一步             |

**反对**：不做"恭喜获得 XXX"的弹窗打断——桌宠是放松产品，解锁应是"自然发生"而非"系统宣告"。

## 6. 解锁节奏曲线

| 阶段   | 解锁频率             | 目的                       |
| ------ | -------------------- | -------------------------- |
| 首日   | `[P]` 3-5 个         | 快速建立"有东西可收集"认知 |
| 首周   | `[P]` 每 1-2 天 1 个 | 维持新鲜感，培养回头习惯   |
| 2-4 周 | `[P]` 每 3-5 天 1 个 | 节奏放缓，避免贬值         |
| 1 月后 | `[P]` 每周 1 个      | 长期玩家持续有目标         |
| 终局   | 稀有/隐藏内容        | 老玩家探索驱动             |

**关键**：早期密、后期疏。早期靠密集解锁建立习惯，后期靠稀有内容维持探索。绝不前期疏（玩家流失）或后期密（内容贬值）。

## 7. 成功条件 (Success Condition)

| 验证项   | 标准                                       |
| -------- | ------------------------------------------ |
| 目标可见 | 玩家随时能说出"下个解锁是什么/还差多少"    |
| 无负担   | 玩家不觉得"必须做某事才能解锁"             |
| 惊喜感   | 解锁瞬间玩家有正向情绪（非"终于"的解脱感） |
| 回头率   | 解锁后玩家次日留存 > `[P]` 60%             |
| 不贬值   | 玩家不会因解锁太容易而觉得"没意义"         |

## 8. 失败状态 (Failure State)

| 失败       | 表现                   | 根因                     | 修复方向                 |
| ---------- | ---------------------- | ------------------------ | ------------------------ |
| 目标不可见 | 玩家不知道还能解锁什么 | 收集册 UI 不清晰         | 强化进度展示             |
| 肝感       | 玩家觉得"得刷"         | 解锁条件强制互动         | 改为被动累计             |
| 贬值       | 解锁太容易无成就感     | 节奏太快                 | 拉长后期节奏             |
| 流失       | 玩家解锁几个就不玩了   | 内容吸引力不足或目标太远 | 优化内容质量 + 中期目标  |
| 焦虑       | 玩家怕"错过"限定内容   | 限时解锁设计             | 不做限时（除非付费 DLC） |

## 9. 边界情况 (Edge Cases)

| 情况                     | 处理                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 玩家同时达成多个解锁条件 | 依次展示，不堆叠（避免仪式感稀释）                           |
| 玩家离线很久回来         | 不补发"错过的"解锁，按当前状态正常推进                       |
| 玩家作弊改存档解锁全部   | 不主动对抗（单机产品），但收集册标记"合法解锁" vs "强制解锁" |
| 解锁内容依赖未拥有的皮肤 | 解锁顺序保证基础皮肤先获得                                   |
| 玩家卸载重装             | 云存档恢复进度（Steam Cloud）                                |

## 10. 调优杠杆

详见 [05-调优变量表.md](../05-调优变量表.md)：

| 杠杆           | 假设值       | 调优目的           |
| -------------- | ------------ | ------------------ |
| 各成就阈值     | `[P]`        | 解锁节奏           |
| 首周可解锁总数 | `[P]` 8-12   | 首周新鲜感         |
| 解锁仪式感时长 | `[P]` 2-4s   | 仪式感 vs 打断感   |
| 隐藏内容占比   | `[P]` 15-25% | 探索驱动 vs 挫败感 |

## 11. 依赖关系

| 依赖方向           | 说明                 |
| ------------------ | -------------------- |
| → 自主行为系统     | 解锁新行为加入行为库 |
| → 自定义系统       | 解锁内容可装备       |
| → 显示模块（工程） | 皮肤/道具渲染        |
| → 情绪系统         | 解锁触发 +愉悦       |

## 12. 付费设计（Steam 商业化）

> 待项目负责人确认定价策略，以下为 GameDesigner 建议：

| 内容类型             | 免费 / 付费        | 理由                   |
| -------------------- | ------------------ | ---------------------- |
| 基础皮肤、表情、行为 | 免费（成就解锁）   | 核心体验不应付费墙     |
| 限定/稀有皮肤        | 免费（高难度成就） | 保证收集型玩家有目标   |
| DLC 皮肤包           | 付费               | 外观付费不破坏核心体验 |
| 季节性内容           | 免费（限时成就）   | 活跃社区，但非付费专属 |

**红线**：绝不付费解锁行为/表情（影响核心陪伴体验），仅外观皮肤可付费。

## 13. 待验证假设

1. 首周解锁数量是否合适（太多贬值/太少流失）
2. 隐藏内容占比——多少让玩家有探索欲而非挫败
3. 解锁仪式感时长——2s 够不够，4s 会不会嫌长
4. DLC 皮肤包的定价敏感度（发售后调研）
