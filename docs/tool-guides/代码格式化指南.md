# 代码格式化指南

本项目使用 Pre-commit 框架配合多种格式化工具，确保仓库中的代码和资源文件美观统一，便于维护和阅读。

本项目的代码格式化配置参考了 [MAA (MaaAssistantArknights)](https://github.com/MaaAssistantArknights/MaaAssistantArknights) 项目的优秀实践。

## 完整工作流示例

### 首次设置（新开发者加入）

```bash
# 1. 克隆项目后，确保子模块已初始化（如果还没有）
git submodule update --init --recursive

# 2. 安装 Python 依赖
pip install -r requirements-dev.txt

# 3. 安装 Pre-commit Hooks
pre-commit install

# 4. （可选）运行一次完整检查，确保环境正常
pre-commit run --all-files
```

### 日常开发工作流

```bash
# 1. 在你的开发分支上正常开发、修改文件

# 2. 准备提交前，先添加文件到暂存区
git add .

# 3. 尝试提交（会自动触发 Pre-commit 检查）
git commit -m "feat: 添加新功能"

# 4. 如果 Pre-commit 发现问题并自动修复了，会阻止提交
#    此时你需要重新添加修复后的文件，然后再次提交
git add .
git commit -m "feat: 添加新功能"
```

## 安装步骤

### 1. 安装依赖

确保你的电脑上已经安装了 Python 环境，然后在项目根目录下执行以下命令：

```bash
pip install -r requirements-dev.txt
```

### 2. 安装 Pre-commit Hooks

```bash
pre-commit install
```

安装完成后，每次执行 `git commit` 时，Pre-commit 会自动运行格式化工具检查你的代码。

## 已配置的工具

| 文件类型           | 格式化工具       | 说明                                                             |
| ------------------ | ---------------- | ---------------------------------------------------------------- |
| C/C++              | clang-format     | 自动格式化 C++ 代码（WebKit 风格，参考 MAA 配置）                |
| Python             | ruff             | Python 代码格式化和检查（排除了 SConstruct/SConscript 构建文件） |
| JSON/YAML/Markdown | prettier         | 统一格式化配置文件和文档                                         |
| 通用文件           | pre-commit-hooks | 检查尾随空格、换行符（统一为 LF）、合并冲突、文件末尾换行符等    |

### 工具详情

#### Clang-format

- **用途**: C++ 代码格式化
- **配置文件**: `.clang-format`
- **风格**: WebKit 风格（参考 MAA 项目配置）
- **支持版本**: v21.1.8+
- **配置特点**:
  - ColumnLimit: 120
  - PointerAlignment: Left
  - UseTab: Never（使用空格）
  - C++20 标准

#### Prettier

- **用途**: JSON、YAML、Markdown 格式化
- **配置文件**: `.prettierrc`
- **配置特点**:
  - 统一使用空格，不用 Tab
  - 默认缩进 4 空格
  - YAML/Markdown 使用 2 空格缩进
  - printWidth: 120

#### Ruff

- **用途**: Python 代码格式化和 linting
- **特点**: 超快速的 Python 工具链，替代 black/flake8/isort
- **排除文件**: SConstruct、SConscript 等构建脚本（这些不是标准 Python）

#### Pre-commit-hooks

- **用途**: 通用文件检查
- **包含**:
  - `trailing-whitespace`: 移除尾随空格
  - `end-of-file-fixer`: 确保文件末尾有换行符
  - `check-yaml`: 验证 YAML 格式
  - `check-json`: 验证 JSON 格式
  - `check-merge-conflict`: 检查是否有未解决的合并冲突标记
  - `check-case-conflict`: 检查 Windows 文件名大小写冲突
  - `mixed-line-ending`: 统一换行符为 LF

## 使用方式

### 自动格式化（推荐）

安装 Pre-commit Hooks 后，每次提交代码时会自动运行：

```bash
git add .
git commit -m "你的提交信息"
```

如果有文件需要格式化，Pre-commit 会自动修复并阻止提交，你只需要再次执行 `git add` 和 `git commit` 即可。

### 手动运行所有检查

```bash
pre-commit run --all-files
```

### 手动运行特定检查

```bash
# 只运行 C++ 格式化
pre-commit run clang-format --all-files

# 只运行 Python 格式化
pre-commit run ruff --all-files
pre-commit run ruff-format --all-files
```

### 手动格式化 C++ 代码

```bash
# 格式化单个文件
clang-format -i gdextension/mouse_passthrough_extension/src/mouse_passthrough.cpp

# 格式化目录下所有 C++ 文件
find gdextension -name "*.cpp" -o -name "*.h" | xargs clang-format -i
```

### 跳过检查（紧急情况）

如果确实需要跳过检查（不推荐），可以使用：

```bash
git commit --no-verify -m "紧急提交"
```

## 编辑器集成

### Visual Studio / Visual Studio Code

1. 安装 clang-format 插件
2. 在设置中启用 "Format On Save"
3. 确保项目中的 `.clang-format` 文件被正确识别

### CLion / Qt Creator

这些 IDE 都原生支持 clang-format，只需要在设置中启用并指向项目的 `.clang-format` 配置文件即可。

## 常见问题与解决方案

### 首次运行 Pre-commit

首次运行 `pre-commit run --all-files` 时，可能会发现大量文件被修改，这是正常的！Pre-commit 会：

- 统一所有文件的换行符为 LF
- 移除尾随空格
- 确保文件末尾有换行符

遇到这种情况时，直接添加这些修改并提交即可：

```bash
git add -u
git commit -m "chore: 统一代码格式"
```

### Pre-commit 安装后无法运行

确认你的 Python Scripts 目录已添加到系统 PATH 环境变量中。

### Clang-format 版本问题

如果遇到版本兼容性问题，可以尝试安装特定版本：

```bash
pip install clang-format==21.1.8
```

### Windows 换行符问题

项目配置为统一使用 LF 换行符。如果遇到换行符相关问题，可以运行：

```bash
git add --renormalize .
```

### 子模块文件被修改

子模块（`external/` 目录下）的文件不会被格式化工具检查，保持原样即可。

### SConstruct/SConscript 文件被检查

这些是 SCons 构建文件，不是标准 Python，已在配置中排除。如果需要排除其他文件，修改 `.pre-commit-config.yaml` 的 `exclude` 字段。

### 某些特定文件不需要检查

在 `.pre-commit-config.yaml` 的 `exclude` 字段中添加需要排除的目录或文件即可，例如：

```yaml
exclude: |
  (?x)^(
    external/|
    transparent-pet/addons/|
    .vscode/
  )/
```

### Pre-commit 自动修复了文件，但提交被阻止

这是预期行为！Pre-commit 会自动修复它能修复的问题（如尾随空格、换行符），然后阻止提交。你需要：

1. 查看修复内容：`git diff`
2. 如果满意，添加修复：`git add .`
3. 再次提交：`git commit`

## 提交前检查清单

- [ ] 代码已经过本地编译测试
- [ ] 运行 `pre-commit run --all-files` 检查通过
- [ ] 所有修改都已添加到暂存区
- [ ] 提交信息符合规范（参考 [Git工作流程指南](../Git工作流程指南.md)）
